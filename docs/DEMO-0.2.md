# TaskDock 0.2 DEMO

本机入口：<http://127.0.0.1:4640/#graph>。内置演示是确定性执行，不是模型推理或真实上线探测。本机后台服务依赖电脑在线；启动 `npm run local:start`，停止 `npm run local:stop`。

新检出需要 Node 24+、Git 和 `npm ci`。服务启动后运行 `npm run demo:reliability`，创建共享证据检查、项目上线流程、变更评审流程、人工等待演示；已有同 ID 任务不覆盖。

## 共享与微调

任务关系页按树展开能力 DAG。多个父任务可引用同一子任务的固定正式版本；每次执行仍会新建独立子请求。进入任务“子任务与派生”可添加输入映射，例如 `{"evidence":"evidence"}` 只传这一字段。

本机验收已经完成一个实例：“共享证据检查”派生为“定制证据检查”，后者把 truthy 检查改成明确要求 `evidence=true`。项目上线流程已换绑到定制版；变更评审和人工演示仍引用原版。原版与其他父任务没有被暗改。新检出可按相同步骤自行派生、调试并发布。

要重复这条路径：管理共享子任务→子任务与派生→派生新任务→修改规则配置→执行草稿测试→版本与 Git 晋级。然后在某个父任务草稿里移除旧引用、添加派生版本、传明确字段，重新测试父任务后晋级。未通过当前摘要测试的换绑会返回 409。

定制版需要 `evidence: true`；原来的字符串材料不能满足严格检查。这验证了实际规则差异。模板默认值不是生产证据，不能把填写 true 视作中台探测了真实环境。

## 人工等待与恢复

管理“人工等待与恢复演示”→正式调用，保留示例字段并提交。请求先进入等待回答，此时尚未派工子任务。可关闭窗口、重开“待你处理”，也可停止并启动本地服务：问题、授权、版本和请求 ID 保留。

选择确认值，填写本次说明，提交回答。服务复核授权后继续同一请求；执行尝试会依次显示 waiting_human、waiting_children、succeeded。原始 confirmed=false 保留在原始请求，回答单独留痕。查看子请求只会看到 inputMap 指定的 evidence。

服务暂停授权后新提交会被拒绝；撤销本次授权会停止其请求树，不能靠回答问题重新扩权。失败重试是新 Attempt，仍绑定旧能力与已有证据；外部工具结果不确定时必须先核对。

## 可靠消息

通过“正式调用”创建的 session 凭证只留在当前标签页会话。进入“投递回执”，选择该会话并接收。处理后 ACK；NACK 退避；不 ACK 则租约到期重投同一 message ID。问题、子结果、最终结果可能分别投递，同一 Run 的未确认消息按顺序推进。

维护控制台可看所有队列状态，但没有其他父会话的 capability 就不能代为 ACK。MCP 上层使用 taskdock_receive / ack / nack 完成相同协议。
