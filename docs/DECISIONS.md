# 集中待确认事项

0.2 已采用：能力 DAG＋请求树、固定子版本引用、独立派生、服务签发且只能缩小的授权、持久 Attempt/Effect、人工等待与拉取式 Outbox。以下问题与 DEMO 一起评审，不阻塞本版：

- 是否需要主动通知/回调。目前父会话拉取持久消息并 ACK/NACK，尚未接外部聊天推送；可在同一 Outbox 上增加适配器。
- 哪个真实任务和你自己的 provider 用于首轮模型效果验收。本版真实进程故障和实际 Pi SDK 契约已测，模型响应仍为测试替身，不借用其他软件密钥。
- 外部工具如何声明只读/幂等。当前同阶段、同工具、同参数复用回执；不确定写操作要求核对。连续观测和外部系统幂等键需要下一轮按业务定义。
- 复合能力包怎样跨实例分发依赖。目前共享子能力在本机完成；含本机 release 引用的复合包明确拒绝共享，避免假装依赖可移植。
- 授权默认 24 小时、失败/中断最多 3 次、全树 24 次工具调用、图最多 8 层/40 个展开节点；可以按实际任务调整。历史/投递回执的长期保留与清理策略待确定。
- 桌面本机原生 UI 已走核心链路；物理手机、真实中文输入法组合、恶意插件 OS 沙箱、多租户与分布式调度尚未验收。

## 仍保留的产品与云端选择

开发采用以下默认选择，后续与 DEMO 一起评审，不阻塞本版：

1. 产品名暂用 TaskDock / 任务坞。
2. 本地优先，registry 先提供独立服务与完整本机共享链路；云域名、托管账号、认证与公开策略等待你选择。不创建付费云资源。
3. 默认内置规则运行器；Pi 适配器已接入，但本环境未提供模型 API key，不借用其他软件凭据。需你配置自己的模型后完成真实模型端到端验收。
4. 原始历史永不自动成为共享记忆；学习提案必须审核，更新 draft 后重测晋级。全自动学习与自动晋级策略需要后续定义风险与评测门槛。
5. MCP 先行，A2A 适配后续增加。Skill 只能改善调用纪律，强制隔离由服务端执行。
6. Team 首版采用显式串行阶段，可追溯、易调试；动态拓扑、并行组队和预算优化后续验证。
7. GitHub 私有仓库已在个人账号 hexiao160705-dev 下创建并核验 Private。当前 gh/Git HTTP 未登录，使用已授权 GitHub 连接器同步代码，不向仓库写入任何凭据；公开可见性保持由你手动决定。
