真实 SIGKILL 的“外部动作”使用临时目录中的文件写入作为外部系统替身，并在成功/回执边界注入中断；未向真实 GitHub、飞书或线上服务写入。Pi 测试使用已安装的真实 SDK 和模拟 provider；没有把内置规则当作 AI 降级执行。

`npm ci` 保留 node-domexception 弃用与可选依赖 install scripts 未获允许的提示，未扩大脚本授权。本版支持路径经离线契约检查，真实模型接入仍须单独验收。

## 已发现并修复

1. 首轮浏览器验证中，保存子任务草稿的回包重建了整个编辑表单，快速继续输入会被重置到默认子任务。改为保留表单节点，只更新引用列表和只读标题；通用刷新在输入聚焦时挂起。加入延迟实际 PUT 的验证后，节点身份、焦点、key 和下拉选择均保持。错误测试没有发布到 stable；修复后重新换绑并测试发布。
2. 事务回滚不能留下“成功”的文件投影。归档写入延至提交后；Outbox 写入故障会回滚业务状态，文件写入故障不撤销已提交业务并可重建。两种故障分别注入并通过。
3. 截图审读发现移动树卡片依赖横向滚动才能看到管理按钮，已调整浅层卡片适配；深层图仍允许面板内横向滚动。

## 本机证据位置与复现

测试日志与分层摘要保存在忽略的 `output/taskdock-0.2/`，浏览器截图保存在 `output/playwright/taskdock-v02/`；不提交请求历史、会话凭证或浏览器产物。可分享的汇总见 [0.2.0.json](verification/0.2.0.json)。

`npm run demo:reliability` 通过实际维护 API 安装演示。可选浏览器辅助脚本使用已有 Playwright CLI，会操作演示数据；以 `node scripts/run-ui-check.js ui-layout` 执行布局检查，CLI 可由 `PLAYWRIGHT_CLI` 指定。ui-prepare / ui-resume 是重启前后两步；ui-compose 在干净演示目录创建派生例子，不应反复创建同一固定 ID。

升级前已停止两个服务并备份到本机 `backups/`，恢复队列与历史在迁移后继续保留。最终启动必须核验两个 `/health` 的 service、version、pid、instance 与进程；交付时保持 loopback，不公开部署。
